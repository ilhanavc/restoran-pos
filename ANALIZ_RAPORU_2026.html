🔬 Derinlemesine Teknik Analiz

Mimari Genel Görünüm

Uygulama 4 bağımsız süreçten oluşuyor: Electron main (orchestrator), Express/Node.js API sunucusu (child process, ELECTRON_RUN_AS_NODE ile), Store Bridge (yazıcı köprüsü, child process) ve CallerID SDK Helper (.NET, opsiyonel). Bu ayrım iyi tasarlanmış; bir sürecin çökmesi diğerlerini doğrudan etkilemiyor.

Veritabanı Katmanı

better-sqlite3 ile senkron SQLite kullanımı, tek-instance masaüstü uygulama için doğru seçim. Tüm order/payment/print operasyonları db.transaction() içinde atomik. PRAGMA user_version ile 1 migration versiyonu takip ediliyor; diğer tüm tablolar CREATE TABLE IF NOT EXISTS ile idempotent. DB dosyası %APPDATA%\Restoran POS\pos.db'de, her başlangıçta legacy migration çalışıyor. Günlük otomatik yedek (02:00, 30 gün).

API Katmanı

15 route dosyası, tüm input'larda Zod validation, 5 rate limiter (auth/admin/bridge/printer/waiterCall), Helmet başlıkları, JWT authentication + role-based authorization. Audit log tüm kritik operasyonlarda çalışıyor (57 audit log çağrısı sunucu genelinde). CORS origins env ile konfigüre edilebilir (LAN tablet desteği).

Frontend Katmanı

React 18 + Vite, 15 major component dizini. Context API ile Auth + Toast yönetimi. Socket.io gerçek zamanlı güncellemeler (kitchen/table/takeaway). Recharts ile 4 etkileşimli grafik. XLSX ile Excel export. Tüm UI metinleri Türkçe. Electron'a özel window.electronAPI bridge (contextBridge) ile güvenli IPC.

Yazıcı Sistemi

ESC/POS protokolü, PC857 Türkçe encoding (manuel byte tablosu, iconv-lite bağımlılığı yok) ve Win1254 encoding (iconv-lite ile). 4 fiş şablonu: PAKET KASA, PAKET MUTFAK, MASA MUTFAK, MASA KASA. Per-printer ESC t + skipInit konfigürasyonu. Store Bridge 10s otomatik yeniden başlatma ile dayanıklı.

Test Yapısı

104 test, 12 test dosyasında: unit (encoding, migration, phone normalize, print jobs idempotency, printer preview), integration (auth, orders, payments, reports — supertest ile gerçek HTTP katmanı). In-memory SQLite ile izole test ortamı. Backend %85+ kapsam tahmin ediliyor.

⚠️ Kötü ve Geliştirilmesi Gereken Yönler

1. CI/CD Pipeline Yok

Repo'da .github/workflows/ dizini hiç yok. Her release manuel npm run dist:win ile alınıyor. Paketleme hatası (v1.0.2 iconv-lite krizi) ancak işletmede kurulumdan sonra tespit edilebildi. Yüksek Öncelik

2. Frontend Test Sıfır

104 testin tamamı backend. Tek bir React component testi yok. Büyük UI değişikliklerinde regresyon riski körleşiyor. Orta Öncelik

3. Migration Versiyonlama Yetersiz

Sadece 1 migration PRAGMA user_version ile takip ediliyor. Diğerleri her başlangıçta tekrar çalışan CREATE TABLE IF NOT EXISTS. Test helper'ında 14 ayrı addColumnIfMissing çağrısı var — migration kodu ile test kodu senkronizasyonu manuel yapılıyor, zamanla kayabilir.

4. QR Kod Dış Servise Bağımlı

Garson çağırma QR kodu için api.qrserver.com kullanılıyor. İnternet bağlantısı olmayan veya zayıf WiFi'lı restoranlarda QR görseli yüklenmiyor. Kırılgan

5. Production Loglama Yok

Tüm hatalar sadece console.error() ile basılıyor. Paketlenmiş Electron uygulamasında bu loglar kaybolur; hata sonrası debug imkansızlaşır. Dosyaya log yazma mekanizması yok. Eksik

6. Helmet CSP Devre Dışı

helmet({ contentSecurityPolicy: false }) ile CSP tamamen kapatılmış. Electron renderer'da çalışıyor olsa da, güvenlik başlıklarının yarısı etkisiz kalıyor.

7. Tek Kullanıcı Migration Sistemi

Birden fazla kullanıcı aynı anda migration tetikleyemez (SQLite zaten tek-process). Ama test helper'ında migration kodu kopyalanmış — migrations/run.js'deki sütun eklemeleri değiştiğinde tests/integration/helpers.js'i de güncellemeyi unutma riski var.

8. Rol Değişikliğinde Token Geçersizleşmiyor

Bir kullanıcının rolü değiştirilse bile eski JWT 24 saat geçerli kalmaya devam ediyor. Acil rol kısıtlaması senaryosunda güvenlik açığı.

9. better-sqlite3 ABI Yönetimi

Electron güncellemesi sonrası npm rebuild better-sqlite3 manuel çalıştırılmalı. Testler bazen ABI uyuşmazlığı hatası veriyor. Otomatik algılama yok.

10. Ürün Görseli Yolu Packaged App'te Belirsiz

Görsel yüklemeler server/uploads/products/ altına yazılıyor. Packaged Electron'da bu dizin resources/server/uploads/ altında. Yeniden kurulumda veya güncelleme sonrası görsellerin kaybolup kaybolmadığı test edilmedi.

🚨 Kritik Eksikler
1. CI/CD Pipeline Eksikliği — En Kritik

v1.0.2'deki iconv-lite hatası tam olarak bu eksikten kaynaklandı. dist:prepare scripti çalışıyor ancak paketlenmiş uygulamanın gerçekten açılıp açılmadığını test eden otomatik bir adım yok. Sonraki her bağımlılık değişikliği benzer bir krizi tekrarlayabilir. Çözüm: GitHub Actions ile npm run dist:prepare → smoke test → release upload otomasyonu.

2. Production Log Dosyası Yok — Kritik

Paketlenmiş Electron uygulamasında bir hata olduğunda (server crash, migration hatası, v.b.) loglar erişilemez. console.error yalnızca geliştirici konsolu açıkken görünür. İşletmede bir sorun çıktığında nedenini bulmak çok güç. Çözüm: electron-log paketi ile %APPDATA%\Restoran POS\logs\main.log ve server.log dosyaları.

3. Stok–Sipariş Entegrasyonu Yok — İşlevsel Kritik

Stok takip modülü var, sipariş modülü var, ama birbirleriyle konuşmuyor. Sipariş kaydedildiğinde stok azalmıyor. Bu, restoranın kullanabileceği en temel stok takip senaryosunu engelliyor. Çözüm: Sipariş kalemi oluşturulduğunda ilgili stok hareketi otomatik yaratılmalı.

4. React Error Boundary Yok — UX Kritik

Herhangi bir React component beklenmedik bir hata verirse tüm uygulama boş beyaz ekrana düşer, kullanıcı ne olduğunu anlayamaz ve yardım alamaz. Kasa ortasında siparişi kaybedebilir. Çözüm: Root ve kritik ekranlar (OrderPanel, PaymentModal) için Error Boundary sarmalayıcı.

5. Ürün Görselleri userData'ya Yazılmıyor — Update Güvenliği

Yüklenen görseller resources/server/uploads/products/ altına yazılıyor. electron-builder yeni kurulumda bu dizini sıfırlayabilir veya üzerine yazabilir. Görseller birkaç update sonra kaybolma riski taşıyor. Çözüm: Upload hedefini app.getPath('userData')/uploads/products/ olarak değiştir, static serving'i buna göre güncelle.

6. Frontend Test Sıfır — Uzun Vadeli Bakım Riski

104 testin tamamı backend. React component'leri için tek bir test yok. Büyüyen codebase'de (860 satır ReportsScreen, 323 satır WaiterCallPanel) UI regresyonlarını elle yakalamak giderek zorlaşacak. Çözüm: Kritik component'ler için Vitest + @testing-library/react ile en az 20 frontend testi.
